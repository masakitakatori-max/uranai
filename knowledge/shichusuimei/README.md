# 四柱推命の参照資料

`sources.json` は出生月令と日干に応じて選ぶ139件の資料です。AIの過去回答は含めていません。各項目には出所、原文/注釈/和訳/要約の区別、行番号、本文のSHA-256を保存し、回答で使用した資料を画面から確認できます。

- 窮通宝鑑: ローカルの `穷通宝鉴_和訳.md` から日干・季節・月別の段落を採録。
- 滴天髄: ローカルの `滴天髄_和訳.md` から天干篇と旺衰・体用・通関・寒暖・燥湿・従象・化象・夫妻等を採録。章末要約は「ローカル要約（原文ではない）」と明記。
- 子平真詮: 沈孝瞻本文の「論用神」「論用神成敗救應」から抜粋。各項目のoriginに掲載先URLを記録。徐氏評注とは区別。

本索引は完全な古典全集ではありません。資料の存在とID整合は検証できますが、解釈の正しさの自動保証にはなりません。資料が不足する観点はAIに保留させ、古典中の身分・性差・疾病・夭寿の断定を利用者へ転用しないよう指定しています。

月別資料の該当日干/月、共通理論、二人比較時の夫妻資料を選択します。原局の事実と解釈を混ぜず、出典・命式のIDに戻れる構造で将来の資料追加・専門家校訂を行います。

## 用神判定回路

`POST /api/shichusuimei/yongshen`（本文 `{ "person": 出生情報 }`）と `npm run shichusuimei:circuit -- YYYY-MM-DDTHH:MM male|female [--dry] [--stage 段]` で動く。

1. 第0段（`src/lib/shichusuimeiYongshen.ts`）：旺衰点数、格局の仮説、扶抑・病薬・調候・通関の候補、特殊格の疑いを機械で出す。点数規則は鑑定票3件に合わせた暫定規則で、古典の条文ではない。
2. 旺衰 → 格局・特殊格 → 5つの取用法 → 統合 → 言い換え の5段。前4段はモデルが古典を検索（`search_classics`）・通読（`read_passage`）しながら判定し、最後の言い換えの段が占いを知らない人向けの結論（`plain`）に直す。言い換えでは専門用語（`JARGON`）の使用を禁じ、残っていれば差し戻す。Anthropic API（ツールランナー）と Claude Agent SDK（プロセス内MCP）のどちらでも同じ回路が動く。
3. 各段の出力は、引用が「その段で本文を読んだ節」に実在するか、命式IDが実在するか、流派間の対立規則（R1〜R7、`server/shichusuimei/circuit/schema.ts`）を守っているかをコードで検証し、通らなければ理由を添えて1回だけやり直させる。

古典は `SHICHUSUIMEI_CLASSICS_DIR` の和訳Markdownを見出し・太字ラベル単位で節に分けて使う（IDは `dt-行番号` / `qt-行番号` で同梱抜粋と共通）。ローカルに無い書物は同梱抜粋で補う。子平真詮は抜粋2件しかないため、格局の「成立」と成敗の断定は R7 で禁止している。

効力は `SHICHUSUIMEI_CIRCUIT_EFFORT`（既定 high）。旺衰の段の実測では high 99.7秒／medium 70.0秒で判定は同じだった。個票のメモ欄には `buildSheetMemo()` が言い換えを先に置き、鑑定用の内訳は指定したときだけ足す。
